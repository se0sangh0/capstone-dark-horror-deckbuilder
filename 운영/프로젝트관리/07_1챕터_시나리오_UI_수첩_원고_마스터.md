## 0. 이번 작업의 기준

### 0-1. 1챕터 범위

이번 1챕터는 과거 10층 참고 시나리오가 아니라 현재 프로토타입의 6층 첫 런이다.

`타이틀·오프닝 → 1층 시작 → 2층 전투 경로 3택 → 3층 용병소·교회·용병소 3택 → EVT-01 전환 사건 → 4층 전투 경로 3택 → 5층 화톳불 → 6층 거두는 자 → 탐사 보고서 → 다음 탐사 준비`

- 2층은 세 경로 모두 전투이며 산지 활동 흔적 한 건을 보여 준다.
- 3층은 용병소·교회·용병소 중 하나를 고르고 방어 흔적 한 건을 보여 준다.
- EVT-01은 3층 완료 뒤 4층으로 넘어가기 전에 한 번 발생한다. 맵 노드와 층을 소비하지 않는다.
- 4층은 세 경로 모두 전투이며 피난·보호 흔적 한 건을 보여 준다.
- 플레이어는 2·3·4층에서 경로 하나씩 고른다. 한 런의 핵심 단서는 총 3건이다.
- 대표 경로는 `R02-A → R03-A → R04-A`다.
- 첫 회차의 EVT-01은 무작위 추첨 없이 `evt_cold_camp`로 고정한다.
- 5층과 6층에는 가짜 3지선다를 표시하지 않는다.

`행정적 무감각 → 익숙한 임무 → 손익 선택 → 흔적의 누적 → 정적과 회고 → 보스 대치 → 미해결 질문 → 다음 명령`

## 1. 공통 표시 계약

| 정보 | 표시 위치 | 진행 차단 | 닫기·다음 입력 |
|---|---|---:|---|
| 오프닝 지시 | 자동으로 열린 조사관 수첩 | 예 | 첫 입력은 현재 타자 완성, 다음 입력은 다음 페이지·단계 진행 |
| 이동 경로 | 경로 카드 3장 | 예 | 카드 한 장 선택 |
| 짧은 진입·전투 문구 | 비차단 자막 바 | 아니요 | 자동 소거, 다음 입력 허용 |
| 선택지 사건 | 상단 삽화 1장·본문·버튼이 있는 사건 패널 | 예 | 결과 뒤 우측 하단 `계속하기`, 화면 클릭 |
| 상태 변화 | 결과문 아래 변화 칩 | 아니요 | 실제 상태 적용과 동시에 표시 |
| 핵심 단서 | 화면 하단 차단 자막 | 예 | 우측 하단 `계속하기`, 화면 클릭 |
| 조사관 수첩 | 상단 접착식 세로 패드 | 예 | 첫 입력은 작성 즉시 완료, 다음 입력은 페이지 진행·닫기 |
| 탐사 보고서 | 배경 딤 위 공문서 한 장 | 예 | 우측 하단 `계속하기`, 화면 클릭 |

- 경로 카드의 제목·환경 설명·위험 징조는 조사관 수첩에 원문 그대로 보존한다.
- 결과 상태는 버튼을 확정한 순간 한 번 적용한다. 자막이나 타자 연출의 완료를 상태 적용 조건으로 사용하지 않는다.
- 변화 칩은 명목값이 아니라 실제 변화량과 적용 후 값을 표시한다.
- 선택지 버튼과 서비스 버튼은 기존 버튼 방식을 유지한다.
- 사건 결과, 핵심 단서 자막과 5층 회고에는 별도 `계속` 버튼을 만들지 않는다.
- 시스템은 이 화면들의 우측 하단에 `계속하기`를 표시한다.
- 플레이어가 화면을 클릭하면 다음 단계로 이동한다.
- 시스템은 첫 클릭만 처리하고 상태·기록·보상을 다시 적용하지 않는다.

### 1-1. 입력과 모달 우선순위

한 입력이 두 화면에 동시에 전달되지 않도록 다음 순서를 고정한다.

1. 탐사 보고서와 런 종료 결과 화면이 열려 있으면 그 화면만 입력을 받는다.
2. 사건 결과, 핵심 단서 자막과 5층 회고가 열려 있으면 첫 확인 입력만 받는다. 뒤의 전투·경로·서비스 UI에는 입력을 전달하지 않는다.
3. 선택지 사건이나 용병소·교회 같은 서비스 화면이 열려 있으면 활성 버튼만 입력을 받는다. 빈 화면 클릭은 선택이나 거래로 처리하지 않는다.
4. 조사관 수첩이 열려 있으면 수첩 입력을 먼저 처리한다. 타자가 작성 중일 때 첫 입력은 현재 페이지의 타자만 완성한다. 이미 전문이 보일 때 다음 입력은 페이지를 넘기거나 수첩을 닫는다.
5. 위 차단 화면이 없을 때만 경로 카드와 전투 입력을 받는다. 비차단 자막은 입력을 소비하지 않고 정해진 시간이 지나면 사라진다.

- 같은 프레임에 여러 확인 입력이 들어와도 가장 위 모달의 첫 입력 한 번만 처리한다.
- 모달이 닫힌 입력을 그 아래 화면의 클릭으로 다시 사용하지 않는다.
- 상태·기록·보상은 화면을 띄우기 전에 한 번 확정한다. 확인 입력은 다음 상태로 옮기는 역할만 한다.
- 기본 확인 입력은 마우스 빈 공간 클릭·터치 탭이다. 접근성 입력으로 `Space`, `Enter`와 게임패드 `Submit`을 같은 동작에 연결한다.
- 스크롤, 드래그, 길게 누르기와 버튼 위 클릭은 빈 화면 확인 입력으로 처리하지 않는다. 전체 오프닝 스킵에 길게 누르기를 채택할 경우에만 그 화면에서 별도 입력으로 소비한다.

### 1-2. 핵심 단서 목록 UI

- 시스템은 2·3·4층에서 얻은 핵심 단서의 안정 ID를 중복 없는 집합으로 영속 저장한다.
- 시스템은 클리어·전멸과 관계없이 첫 런의 탐사 보고서를 넘긴 뒤 좌측 고정 UI에 별도 `핵심 단서` 아이콘을 해금한다.
- 핵심 단서 아이콘은 조사관 수첩과 다른 버튼으로 표시한다.
- 아이콘에는 `핵심 단서 {발견 수}/9 · {달성률}%`를 표시한다.
- 목록 화면은 발견한 단서만 층별로 보여 준다.
- 미발견 단서의 제목, 빈 슬롯, 실루엣과 설명은 모두 숨긴다.
- 조사관 수첩은 현재 런 기록을, 핵심 단서 목록은 여러 런의 발견 상태를 관리한다.
- 단서 시스템은 제목, 설명, 발견 수와 달성률을 저장하지 않는다. 현재 빌드의 활성 ID 9개와 저장된 발견 ID 집합을 비교해 매번 계산한다.
- `발견 수`는 활성 ID와 저장된 ID의 교집합 크기다. `달성률`은 `floor(발견 수 × 100 / 9)`로 계산한다. 예: 3종 발견 시 `3/9 · 33%`.
- 첫 보고서를 넘겼는지는 완료 런 수로 판단한다. 단서 아이콘 전용 해금 불리언을 따로 저장하지 않는다.
- 아이콘을 열면 층·경로 순으로 발견 기록 목록을 보여 준다. 항목을 고르면 제목·그림·화면 자막·수첩 문장을 보는 상세 화면으로 이동하며 `뒤로`와 `닫기`를 제공한다.
- 발견 기록이 없으면 `등록된 탐사 기록이 없습니다.`를 표시한다. 재발견한 ID는 새 항목이나 발견 수를 만들지 않고 기존 상세만 다시 열 수 있다.
- 상위 차단 모달이 열려 있으면 핵심 단서 아이콘을 비활성화한다. 좌측 패널을 접어도 해금된 아이콘은 고정 영역에 남긴다.
- 발견 ID와 현재 런 기록을 같은 처리에서 저장하지 못하면 진행을 멈추고 `탐사 기록을 저장하지 못했습니다. 다시 시도해 주세요.`와 `다시 시도`를 표시한다. 저장 성공 전에는 자막·수첩·달성률을 먼저 확정하지 않는다.
- 단서 이미지만 불러오지 못한 경우 `이미지를 불러오지 못했습니다.`를 이미지 영역에 표시하되 문안 열람과 진행은 막지 않는다.

### CH1-S01 · 이전 탐사 결과

조사관 수첩이 저절로 열리고 새 기록이 한 글자씩 작성된다. 탐사국의 지시는 수첩으로만 전달한다.

**수첩 페이지 제목**: `이전 탐사 결과`

> 이전 탐사대와의 연락이 두절되었다.\
> 해당 임무는 실패로 종결한다.

- 첫 입력은 작성 중인 본문을 즉시 완성한다. 페이지는 넘어가지 않는다.
- 전문이 보인 뒤 다음 입력은 페이지를 위로 넘기고 `CH1-S02` 작성을 시작한다.

### CH1-S02 · 후속 투입 통보

**수첩 페이지 제목**: `후속 투입 통보`

> 후속 투입 절차가 승인되었다.\
> 교전 수칙 숙지 후 즉시 현장으로 이동하라.

투입 대상은 이름과 번호 없이 `조사관`으로만 적는다.

- 첫 입력은 작성 중인 본문을 즉시 완성한다.
- 전문이 보인 뒤 다음 입력은 수첩을 닫고 `CH1-S03`으로 이동한다.
- 입력은 수첩 옆 빈 공간 클릭 또는 `Space`를 사용한다.
- 두 페이지 전체를 한 번에 건너뛰는 방식은 아직 정하지 않았다. 전체 스킵과 페이지별 2입력을 같은 동작으로 묶지 않는다.

새 런에 필요한 파티·경로 정의·수첩 상태 초기화가 하나라도 실패하면 부분 상태를 폐기하고 타이틀에 머문다. 화면에는 `탐사를 시작하지 못했습니다. 다시 시도해 주세요.`와 `다시 시도` / `타이틀로`를 표시한다. 실패한 시도는 런 번호·영혼석·완료 런 수·핵심 단서 발견 집합을 바꾸지 않는다.

### CH1-S03 · 1층 탐사 개시

- 비차단 자막: `탐사 개시. 오늘도, 어제처럼.`
- 최초 경로 선택 안내: `이동 후보 3건이 확인되었습니다. 각 기록의 징조를 비교할 수 있습니다.`
- 최초 경로 기록 안내: `현장 기록 갱신: 선택 경로가 수첩에 추가되었습니다.`
- 첫 전투 가이드 제목: `전투 안내`
- 안내 1: `① 손패의 카드를 선택하면 공용 스택이 쌓입니다.`
- 안내 2: `② [턴 종료] 선택 시 이번 턴이 확정됩니다.`
- 안내 3: `③ 동료는 쌓인 스택에 맞춰 자동으로 행동합니다.`
- 가이드 완료 기록: `교육 이행 확인 · 현장 투입 승인`

발생 순서는 `오프닝 완료 → 1층 개시 자막 → 2층 경로 안내 1회 → 경로 선택 → 수첩 아이콘 강조와 기록 안내 1회 → 첫 전투 진입 → 전투 가이드 1회`다. 경로 안내와 수첩 강조 문구는 3·4층에서 반복하지 않는다. 전투 가이드는 시스템 사용법이며 탐사국의 새 서사 지시로 취급하지 않는다.

## 3. 2층 · 산지 활동 흔적

### R02-A · 발자국이 남은 숲길 · 대표 경로

**경로 카드**

- 제목: `발자국이 남은 숲길`
- 환경: `낮은 수풀 사이로 좁은 길이 이어진다.`
- 징조: `잘린 덩굴과 뒤엉킨 발자국이 보인다.`

**공개 장소**: `수풀 사이 숲길`

- 전투 진입 자막: `적대 개체 감지. 교전 상태로 전환된다.`
- 전투 승리 자막: `구역 정리 완료. 회수분이 확인된다.`

### 3-1. 2·4층 공통 전투 결과

2층과 4층의 세 경로는 모두 전투로 이어진다. `R04-C`는 엘리트 전투지만 같은 승패·기록 순서를 사용하며 오브제 선택 화면은 열지 않는다.

적 전멸과 아군 전멸이 같은 판정에서 함께 성립하면 아군 전멸을 우선한다. 승패를 확정한 뒤에는 아래 순서를 한 번만 실행한다.

**승리**

1. 승리와 영혼석 실제 획득량을 확정한다.
2. 경로·장소·전투 결과와 선택한 핵심 단서를 수첩 사건 한 건으로 완성한다.
3. 핵심 단서 ID를 영속 발견 집합에 추가한다. 이미 있으면 중복 추가하지 않는다.
4. 차단 전투 결과 화면에 `전투 승리`, `영혼석 +{실제 획득량}`과 우측 하단 `계속하기`를 표시한다.
5. 첫 화면 클릭 뒤 선택한 핵심 단서의 차단 자막을 표시한다.
6. 단서 자막 우측 하단에 `계속하기`를 표시한다. 다음 첫 화면 클릭 뒤 다음 층으로 이동한다.

```text
[제 {floor}구역 현장 기록]
경로: {routeTitle}
관찰: {routeEnvironment}
징조: {routeOmen}
확인 장소: {revealedLocation}
조치: 교전
결과: 승리 · 영혼석 +{실제 획득량} → 보유 {현재 보유량}
{경로별 수첩 사후 관찰 문장}
```

**전멸**

1. 추가 전투 입력을 잠그고 전멸과 소실 인원을 확정한다.
2. 비차단 자막 `교전 종료. 생존 인원이 확인되지 않는다.`를 표시한다.
3. 경로·장소·전멸 결과를 수첩 사건 한 건으로 완성한다.
4. 차단 결과 화면에 제목 `탐사대 소실`, 결과 `제 {reachedFloor}구역에서 기록 중단`, 우측 하단 `계속하기`를 표시한다.
5. 첫 확인 입력 뒤 전멸 탐사 보고서로 이동한다. 자동 시간 경과만으로 보고서로 넘기지 않는다.

```text
[제 {floor}구역 현장 기록]
경로: {routeTitle}
관찰: {routeEnvironment}
징조: {routeOmen}
확인 장소: {revealedLocation}
조치: 교전
결과: 탐사대 소실
```

- 전멸한 전투의 핵심 단서는 획득·표시·기록하지 않는다.
- 전멸 전에 다른 층에서 얻은 핵심 단서는 영속 발견 집합에 남는다.
- 전멸 결과 화면과 보고서는 상태·기록·보상을 다시 적용하지 않는다.

## 4. 3층 · 정비 경로와 방어 흔적

3층은 경로 카드 3장을 표시한다. `R03-A`와 `R03-C`는 용병소, `R03-B`는 교회로 이어진다. 두 용병소는 같은 서비스 기능과 비용을 사용하며 경로 문구와 핵심 단서만 다르다.

### 4-1. 용병소 공통 문구

- 진입 자막: `인력 수급소. 지원자는 언제나 충분하다. 그게 문제다.`
- 메인 버튼: `고용` / `파티 편집` / `나가기`
- 고용 화면: `보유 영혼석 {현재값}` / `리롤 ({현재 비용})` / `예비대 ({현재 인원}/9)` / `동료 명단 보기`
- 후보 표기: `{역할명} · {런 내 두 자리 일련번호}`
- 후보 행동: `고용 ({모집 비용})`
- 리롤 성공: `후보 명단 갱신 완료 · 영혼석 -{비용} · 보유 {잔액}`
- 고용 성공: `구현체 배치 완료 · 영혼석 -{비용} · 보유 {잔액}`
- 영혼석 부족: `영혼석이 부족합니다 (필요 {비용})`
- 공간 부족: `파티와 예비대가 가득 찼습니다.`
- 나가기: `나가기`

용병소 수첩은 한 방문을 사건 한 건으로 묶는다. 리롤·고용·파티 편집은 실제로 성공한 순서대로 적는다. 영혼석 부족, 공간 부족, 취소와 변화 없는 파티 편집은 화면 피드백만 보여 주고 거래 내역에 남기지 않는다.

```text
[제 3구역 현장 기록]
경로: {routeTitle}
관찰: {routeEnvironment}
징조: {routeOmen}
확인 장소: 용병소
조치: 인력 정비
결과: {성공한 서비스 결과를 발생 순서대로 표시}
{경로별 수첩 사후 관찰 문장}
```

- 리롤 성공: `후보 명단 갱신 완료 · 영혼석 -{비용} → 보유 {잔액}`
- 고용 성공: `{역할명 · 런 내 두 자리 일련번호} 고용 · 영혼석 -{비용} → 보유 {잔액}`
- 실제 편성이 바뀐 파티 편집: `파티 편성 변경`
- 성공한 서비스가 없으면 `조치` 줄을 생략하고 `결과: 이용 내역 없음`으로 적는다.
- 핵심 단서 문장은 방문 기록의 마지막 줄에 한 번 붙인다. 수첩 기록을 완성한 뒤 핵심 단서 차단 자막을 별도로 보여 준다.
- 파티 편집은 전투 가능한 동료가 0명이 되는 구성을 확정할 수 없다. `파티 인원이 없습니다. 최소 1명을 편성해야 이동할 수 있습니다.`를 표시하고 `나가기`를 막는다.

- 진입 자막: `미등록 구조물. 탐사국 시설망과 일치하지 않는다.`
- 화면 제목: `교회`
- 잔액: `영혼석 {현재값}`
- HP 버튼: `전원 HP +50 · 영혼석 30`

- HP 회복 결과: `회복 처리 완료.` + 동료별 `HP +{실제 회복량} → {최종 HP}` + `영혼석 -30 → {잔액}`
- 스트레스 완화 결과: `안정 처리 완료.` + 동료별 `스트레스 -{실제 감소량} → {최종 스트레스}` + `영혼석 -20 → {잔액}`

- 파티 전원의 스트레스가 0이면 스트레스 완화 버튼을 비활성화하고 `전원 스트레스가 이미 최소입니다.`를 표시한다.
- 실제 변화 대상이 없는 서비스는 비용을 차감하거나 성공 거래·수첩 내역을 만들지 않는다. 거래 처리 중에는 같은 버튼의 연타 입력을 잠근다.

교회 수첩도 한 방문을 사건 한 건으로 묶는다. 성공한 서비스만 발생 순서대로 기록한다. 영혼석 부족, 부활 대상 없음, 빈자리 없음, 취소는 화면 피드백만 보여 주고 거래 내역에는 남기지 않는다.

```text
[제 3구역 현장 기록]

징조: 약 냄새와 낮은 기도 소리가 섞여 온다.
확인 장소: 교회
조치: 정비
결과: {성공한 서비스 결과를 발생 순서대로 표시}
주변 탐색 결과 협곡 길목의 통나무·돌 장벽과 바깥 향 배치를 확인함.
```

서비스 한 건의 기록 순서는 `서비스 완료 문구 → 동료별 실제 변화 줄 → 비용·잔액 줄`이다. 동료 변화 줄은 대상마다 반복하지만 비용과 잔액은 서비스당 한 번만 적는다.

```text

{역할명 · 런 내 일련번호} HP +{실제 회복량} → {최종 HP}
{대상 동료 수만큼 반복}

```

```text

{역할명 · 런 내 일련번호} 스트레스 -{실제 감소량} → {최종 스트레스}
{대상 동료 수만큼 반복}
```

|---|---|---|---|
| `휴식하기` | HP | `일행이 화덕에 새 불을 지피고 짧게 쉰 뒤 진행한다.` | 동료별 `HP +{실제 회복량} → {최종 HP}`. 명목 회복량은 30 시험값 |
| `흩어져서 살펴보기` | HP·스트레스·영혼석 | `일행이 흩어져 물건을 조사하던 중 짐 뒤의 괴생물체를 쫓아낸다. 회수한 물건에서 영혼석을 확보한다.` | 동료별 `HP -{실제 감소량} → {최종 HP}`, `스트레스 +{실제 증가량} → {최종 스트레스}`, 파티 `영혼석 +15 → {보유량}` |

- 위험 조사의 적용 순서는 `HP 감소 → 스트레스 증가 → 영혼석 지급`이다.
- `휴식하기`는 생존 중인 활성 파티 동료마다 `min(최대 HP, 적용 전 HP + 30)`을 적용한다.
- `흩어져서 살펴보기`의 HP는 생존 중인 활성 파티 동료마다 `max(1, 적용 전 HP - 20)`을 적용한다.

- 예비대와 사망 동료는 HP·스트레스 변화 대상에서 제외한다. 영혼석 15는 대상 수나 실제 변화량과 관계없이 파티에 한 번만 지급한다.
- `지나치기`는 상태·재화·파티 구성을 바꾸지 않는다.
- 결과 상태와 `ChoiceResolved` 기록은 선택 버튼을 확정한 순간 한 번 생성한다. EVT-01은 전투, `BattleResolved`, 전투 보상과 핵심 단서를 만들지 않는다.
- 결과를 적용한 뒤 선택지 버튼을 숨긴다.
- 우측 하단에 `계속하기`를 표시한다.
- 플레이어가 화면을 클릭하면 4층 경로 카드로 이동한다.
- 선택지마다 별도 이미지를 표시하지 않는다.

### 7-1. HP 50% 자막 트리거와 대기열

- 거두는 자의 현재 HP가 처음으로 최대 HP의 50% 이하가 된 직후 문구를 한 번 예약한다.
- 같은 피해 판정으로 HP 50% 이하 진입과 처치가 함께 성립하면 HP 50% 문구를 생략하고 처치 문구만 표시한다.
- 다른 비차단 전투 자막이 표시 중이면 HP 50% 문구를 자막 대기열 뒤에 넣는다. 현재 문구가 자동 소거된 뒤 순서대로 표시한다.
- 대기열 자막은 전투 진행을 막지 않는다. 다단 히트, HP 회복 뒤 재하락과 전투 화면 재진입으로 다시 예약하지 않는다.
- 1회 표시 상태와 자막 대기열은 전투 단위 상태다. 새 런 영속 데이터로 저장하지 않는다.

HP 50% 문구는 첫 회차 T0 기본 문구 `로브 안쪽에서, 당신을 닮은 얼굴이 흘깃 보였다.`를 그대로 사용한다. 이 대기열은 구현 요구이며 일반 로그 문자열을 즉시 덮어쓰는 방식으로 대체하지 않는다.

### 7-2. 승리 화면과 보고서 이동

1. 보스 처치 판정과 비차단 처치 자막 `그것이 쓰러졌다. 그런데 낫질 소리는, 아직 멈추지 않았다.`를 확정한다.
2. 이번 런 영혼석 실제 획득량과 6층 전투 수첩 사건을 한 번 확정한다.
3. 차단 승리 화면을 표시한다.
   - 제목: `핵심 개체 제거`
   - 결과: `영혼석 +{실제 획득량}`
   - 후속: `탐사 보고서 작성 중…`
   - 우측 하단: `계속하기`
4. 첫 화면 클릭 뒤 클리어 탐사 보고서로 이동한다.

별도 `보스 처치 / 엔딩` 임시 팝업은 사용하지 않는다. 확인 입력은 이미 확정한 보상과 수첩 사건을 다시 적용하지 않는다.

### 7-3. 전멸 화면과 보고서 이동

1. 전멸 판정과 비차단 자막 `탐사대 전멸. 다음 탐사대가 이미 편성되었다.`를 확정한다.
2. 소실 동료 목록, 이번 런 총획득 영혼석과 6층 전멸 수첩 사건을 한 번 확정한다.
3. 차단 결과 화면을 표시한다.
   - 제목: `탐사대 소실`
   - 결과: `제 6구역에서 기록 중단`
   - 우측 하단: `계속하기`
4. 첫 화면 클릭 뒤 전멸 탐사 보고서로 이동한다.

별도 재도전 버튼은 표시하지 않는다. 전멸 결과 화면을 시간 경과만으로 넘기지 않는다.

## 8. 조사관 수첩 기록 계약

### 8-1. 공통 양식

```text
[제 {floor}구역 현장 기록]
경로: {routeTitle}
관찰: {routeEnvironment}
징조: {routeOmen}
확인 장소: {revealedLocation}
조치: {confirmedAction}
결과: {confirmedResult}
```

- 발생하지 않은 항목은 빈 줄로 남기지 않고 생략한다.
- 경로 선택과 장소 공개를 각각 새 사건으로 쪼개지 않는다. 한 장의 경로 기록을 장소 공개 시 완성한다.
- 전투는 전투당 사건 한 건으로 기록한다.
- 핵심 단서는 해당 전투·서비스 기록의 마지막 줄에 붙인다.
- 동료는 `{역할명} · {런 내 두 자리 일련번호}`로 표시한다. 개인 이름은 표시하지 않는다.

### 8-3. 다음 탐사 지시 수첩 전문

클리어·전멸 보고서를 넘긴 뒤 새 지시는 조사관 수첩에만 추가한다.

**수첩 페이지 제목**: `차기 탐사 편성 통보`

> 제 {nextRunNumber}차 탐사 편성이 승인되었다.\
> 교전 수칙 숙지 후 즉시 현장으로 이동하라.

- `{nextRunNumber}`는 현재 보고서의 런을 마감한 뒤 계산한 다음 런 번호다.
- 수첩이 자동으로 열리고 본문을 한 글자씩 작성한다.
- 첫 입력은 타자를 완성하고 다음 입력은 수첩 확인을 끝낸다.
- 이 페이지를 닫은 뒤의 최종 목적지는 아직 정하지 않았다. 타이틀, 다음 탐사 준비 화면과 즉시 새 런 시작 중 하나를 사용자 결정 뒤 연결한다.

## 9. 탐사 보고서

### 9-1. 클리어 전문

```text
괴이탐사국
정기 탐사 결과 보고서                         [기밀]

탐사 번호     제 {runNumber}차 정기 탐사
결과         임무 완수
최종 도달     제 6구역 · 성소

회수량       영혼석 {이번 런 총획득량}
제거 개체     {처치 개체 총수}

인원 변동
 투입 {초기 투입 인원} · 복귀 {생존 인원} · 소실 {사망 인원} · 재편성 {부활 인원}
 ~~{역할명} · {런 내 두 자리 일련번호}~~ — 제 {소실 구역}구역, 기록 말소

특이 접촉     {선택지 사건 수}건
 제 3구역: 식어 있는 야영지 — {EVT-01 선택별 결과 1줄}

패닉 발생 보고 {panicCount}건

기록 요약
 제 2구역 핵심 단서 1건 · {2층 단서 제목}
 제 3구역 핵심 단서 1건 · {3층 단서 제목}
 제 4구역 핵심 단서 1건 · {4층 단서 제목}

비고: 위협 분류와 현장 흔적 사이의 불일치는 미해결로 남긴다.

본 보고서는 열람 후 자동 폐기됩니다.
확인하면 다음 탐사 지시가 조사관 수첩에 추가됩니다.

그들은 무엇을 지키고 있었나.
                                        [계속하기]
```

- 회수량은 현재 보유량이 아니라 이번 런의 총획득량을 사용한다.
- 층마다 경로 하나를 골랐으므로 각 핵심 분류는 1건씩 기록한다.
- 첫 회차에는 `완료는 몇 번째인가.`를 표시하지 않는다.
- 소실 동료가 없으면 취소선 하위 줄을 모두 생략한다. 있으면 실제 소실 순서대로 한 줄씩 표시한다.
- EVT-01 결과 줄은 선택에 따라 아래 문구 중 하나를 사용한다.
  - 휴식하기: `화덕에서 휴식, 생존 동료 전원 회복`
  - 흩어져서 살펴보기: `현장 수색 중 괴생물체 격퇴, 영혼석 회수`
  - 지나치기: `현장 미접촉`
- 정상 첫 런에서는 EVT-01이 한 번 발생한다. 예외로 선택지 사건이 0건이면 대표 사건 줄을 생략한다.

### 9-2. 전멸 전문

```text
괴이탐사국
정기 탐사 결과 보고서                         [기밀]

탐사 번호     제 {runNumber}차 정기 탐사
결과         탐사대 소실
최종 도달     제 {reachedFloor}구역

회수량       영혼석 {이번 런 총획득량}
제거 개체     {처치 개체 총수}

인원 변동
 투입 {초기 투입 인원} · 복귀 0 · 소실 {사망 인원}
 ~~{역할명} · {런 내 두 자리 일련번호}~~ — 제 {소실 구역}구역, 기록 말소

특이 접촉     {선택지 사건 수}건
 제 3구역: 식어 있는 야영지 — {EVT-01 선택별 결과 1줄}
패닉 발생 보고 {panicCount}건

기록 요약
 {전멸 전에 확보한 핵심 단서만 층 순서대로 표시}
 제 {floor}구역 핵심 단서 1건 · {단서 제목}

현장 기록 부족. 후속 탐사가 필요하다.

본 보고서는 열람 후 자동 폐기됩니다.
대체 인력 편성이 완료되었습니다.
확인하면 다음 탐사 지시가 조사관 수첩에 추가됩니다.
                                        [계속하기]
```

전멸 보고서에는 핵심 단서 수와 관계없이 마지막 질문을 표시하지 않는다.

- 소실 동료 줄은 실제 인원만큼 반복한다.
- EVT-01이 발생하기 전에 전멸했다면 특이 접촉은 `0건`으로 표시하고 대표 사건 줄을 생략한다.
- 기록 요약에는 전멸 전에 획득을 확정한 핵심 단서만 표시한다. 아직 도달하지 못했거나 그 층 전투에서 전멸해 얻지 못한 단서 줄은 생략한다.
- 확보한 단서가 0건이면 `기록 요약` 제목과 하위 줄을 모두 생략한다.
- 보고서의 단서 요약은 현재 런 스냅샷의 `acquiredClueIdsByFloor`를 읽는다. 여러 런의 영속 발견 집합을 그대로 나열하지 않으며 보고서에서 발견 상태를 다시 변경하지 않는다.

### 9-3. 보고서 확인 뒤 처리 순서

클리어·전멸 보고서는 우측 하단 `계속하기`를 표시하며 화면 클릭으로 넘긴다. 첫 클릭만 아래 순서를 실행한다.

1. 보고서에 사용한 스냅샷을 확정하고 현재 런을 마감한다.
2. 완료 런 수를 1 증가시키고 `{nextRunNumber}`를 계산한다.
3. 첫 보고서였다면 완료 런 수를 기준으로 좌측 핵심 단서 아이콘을 해금한다.
4. `차기 탐사 편성 통보` 페이지를 조사관 수첩에 추가하고 수첩을 자동으로 연다.
5. 수첩의 첫 입력은 타자를 완성하고 다음 입력은 페이지 확인을 끝낸다.
6. 첫 해금인 경우 수첩이 닫힌 뒤 `ch1.clue.unlocked` 안내를 표시한다. 해금 토스트와 수첩을 동시에 띄우지 않는다.
7. 해금 안내가 끝난 뒤 사용자가 확정할 최종 목적지로 이동한다.

`ch1.clue.unlocked`는 탐사국 지시가 아닌 UI 상태 안내다.

> 핵심 단서 목록이 열렸습니다. 좌측에서 지금까지 확인한 기록을 볼 수 있습니다.

런 마감, 완료 런 수 증가, 지시 페이지 추가와 해금 처리는 재클릭으로 반복하지 않는다. 보고서 뒤 최종 목적지는 사용자 결정 전까지 구현값으로 고정하지 않는다.

보고서 본문은 1280×720에서도 좌측 고정 UI와 우측 하단 `계속하기`를 가리지 않는 안전 여백 안에서 스크롤할 수 있어야 한다. 스크롤·드래그는 보고서 확인으로 처리하지 않으며, 끝까지 내리도록 강제하지 않는다. `계속하기`는 보고서가 열린 뒤 바로 사용할 수 있다.

6. CH1-U09 · §13-4의 런 포기 문구와 번호 처리 승인 여부.

### 14-3. 핵심 단서 영속 저장

단서 저장 문서는 `schemaVersion`과 `discoveredClueIds: HashSet<string>`를 가진다. 아이콘 해금은 완료 런 수에서 계산하므로 별도 불리언으로 중복 저장하지 않는다.

- 단서 획득을 확정할 때 ID를 추가하고 즉시 저장한다.
- 클리어, 전멸, 런 포기, 새 런과 앱 재실행 뒤에도 유지한다.
- `title`, `subtitle`, `notebook`, `imageKey`, 발견 수, 전체 수와 달성률은 저장하지 않는다.
- 현재 빌드의 활성 단서 ID는 콘텐츠 카탈로그에서 읽는다. 발견 수와 달성률은 §1-2 식으로 계산한다.
- 첫 런 뒤 아이콘 해금은 완료 런 수가 1 이상인지로 판단한다. 단서 저장에 해금 불리언을 추가하지 않는다.
- CH1-D8 확정 전 후보와 최종 안정 ID가 같으므로 이번 확정에는 ID 이관이 필요하지 않다. 이후 안정 ID를 바꿀 때만 별도 이관표를 승인한 뒤 적용한다.
- 알 수 없는 과거 ID는 삭제하지 않고 격리해 보존한다. 승인된 D8 이관표가 있을 때만 새 ID로 한 번 변환하고 `schemaVersion`을 올린다.

### 14-4. 방문 기록과 보고서 스냅샷

`ServiceVisitRecord`는 한 장소 방문의 성공 결과만 발생 순서대로 가진다.

| 필드 | 내용 |
|---|---|
| `floor`, `routeId`, `locationKey` | 경로와 장소 |
| `successfulTransactions` | 성공한 리롤·고용·파티 변경·회복·안정·부활 목록 |
| `clueId` | 방문 완료 뒤 붙이는 경로 핵심 단서 |
| `dedupKey` | 같은 방문 기록의 중복 생성을 막는 키 |

교회 거래는 `serviceType`, 동료별 `before`, `actualDelta`, `after`, `cost`, `balanceAfter`를 가진다. 비용과 잔액은 서비스 한 건에 한 번만 저장한다.

`RunReportSnapshot`은 보고서를 열기 직전에 현재 런 상태를 복사해 만든다. 최소 필드는 다음과 같다.

- `runNumber`, `result`, `reachedFloor`
- `soulstoneGainedThisRun`, `defeatedEnemyCount`
- `initialCount`, `survivorCount`, `losses`, `revivalCount`, `panicCount`
- `choiceEventCount`, `evt01ChoiceId`
- `acquiredClueIdsByFloor`

보고서 UI는 이 스냅샷만 읽는다. 보고서를 다시 그리거나 넘겨도 재화·단서·완료 런 수를 다시 바꾸지 않는다.

현재 런을 마감한 뒤에는 이전 `runRecords`에 새 지시를 붙이지 않는다. 별도 `PostRunFlowState`가 `{nextRunNumber}`, `nextAssignmentPagePending`, `clueUnlockToastPending`을 들고 다음 지시 수첩과 해금 안내의 표시 순서를 관리한다. 수첩 확인 뒤 목적지 선택은 §13-5가 끝날 때까지 이 상태의 미결 분기로 둔다.

### 14-5. 중복 방지와 초기화

- 상태 적용과 사건 기록 생성은 같은 처리 안에서 한 번 확정한다.
- 경로, 전투, 서비스 방문, EVT-01, 화톳불, 보스 결과와 보고서 마감에는 서로 다른 `dedupKey`를 쓴다.
- 새 런은 현재 런 상태, 수첩 사건, EVT 소비 목록, 5층·보스·보고서 1회 플래그를 초기화한다.
- 새 런 초기화는 영속 `discoveredClueIds`와 완료 런 수를 지우지 않는다.
- 런 포기는 현재 런 상태와 수첩 사건을 폐기하되 이미 저장한 핵심 단서 발견 ID는 유지한다.

### 15-2. 공통 표현 기준

- 마스터 원본은 기존 두 장과 같은 `1024×1536`, 2:3 세로형, 8비트 RGB PNG, 알파 없음으로 제작한다.
- 중심 단서는 화면의 가운데 80% 안전 영역 안에 두고, 상하·좌우 10%는 UI 크롭에서 잘려도 핵심 정보가 사라지지 않는 배경 여백으로 둔다.
- Unity 원본 경로는 `Assets/Resources/ResultImage/`를 유지한다. `Sprite (2D and UI)`, `Single`, sRGB로 가져오며 출시 압축값은 1280×720·1920×1080 화면 QA 뒤 확정한다.
- `T0 / FILTERED` 시점의 물리적 관찰만 그린다.
- 인물보다 물건·배치·방향·소모 상태가 먼저 보이게 한다. 조사관이나 동료를 화면 중심에 크게 두지 않는다.
- 침략·수탈·현지 주민·어린 토착신의 정체를 직접 드러내지 않는다.
- 내부 제작 축의 결론을 그림 안의 문자나 상징으로 설명하지 않는다.
- 이미지 안에 제목과 설명 문구를 굽지 않는다. UI 문자열과 분리해 locale 변경 가능성을 남긴다.
- 원본 비율과 해상도는 위 값으로 고정한다. 차단 자막에도 그림을 함께 보여 줄지, 해금 목록 상세에서만 쓸지는 §13-5 결정 뒤 화면별 크롭 규칙을 확정한다.
