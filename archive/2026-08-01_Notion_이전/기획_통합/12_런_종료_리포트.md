## 1. 개요 · 의도

런이 끝나면 **클리어·전멸 모두 즉시 탐사국 공문서 양식의 "탐사 보고서" 화면을 1장 표시**한다. 단순 타이틀 직행은 사용하지 않는다. 오프닝의 실패 요원 보고서(S01)와 같은 타자기 문서 톤을 사용해, **이전 요원의 실패 보고서로 시작한 이야기가 현재 요원의 탐사 보고서로 끝나고 다시 다음 투입을 부르는** 수미상관을 만든다.

**세 가지 역할**
1. **플레이 요약**: 이번 런에서 일어난 일(전투·상실·선택)을 한 화면에
2. **세계관 장치**: 시스템 수치를 관료 문장으로 번역 — "당신의 모험은 탐사국에겐 서류 한 장이다"
3. **다회차 유도**: 누적 통계와 회차 연동 변화(§5)로 "한 번 더"의 서사적 이유 제공

## 2. 기록 항목 (RunRecord)

런 중 자동 수집되는 로그. **플레이어 개입 없음** — 수집 강제 아님 원칙(00 §8)과 동일하게, 읽지 않아도 [확인]으로 넘길 수 있다.

| 항목 | 수집 시점 | 보고서 표기 |
|---|---|---|
| 회차 번호 | 런 시작 | "제 N차 정기 탐사" |
| 결과 | 런 종료 | 클리어: "임무 완수" / 전멸: "탐사대 소실" |
| 도달 층 | 노드 진입마다 갱신 | "최종 도달: 제 N구역" |
| 처치 괴이 수 | 적 사망 이벤트 | "제거 개체: N" |
| 회수 영혼석 (총획득) | 드롭 수거 | "회수량: N — 정상" |
| 지급 마석 | 마석 획득 시점(H1에서 지급처 확정) | "지급 승인: 마석 N" |
| 소실 동료 | 사망 이벤트 (이름·층·사인) | §3 양식 참조 — **이름은 취소선 처리** |
| 이벤트 선택 로그 | 06 이벤트 확정 시 (id+선택지) | "특이 접촉: N건" + 대표 1건 한 줄 |
| 패닉 발생 횟수 | 패닉 발동 | "정신 오염 보고: N건" |
| 오브제 획득/처분 | 획득·마석 교환·계승 | "회수 유물: N (처분: 환수 N / 반출 N)" |
| 부활 시행 | 교회 부활 | "재편성: N건" |

## 3. 보고서 양식 — 발표용 샘플 전문

> 타자기 폰트·한 글자씩 출력(빠르게)·[기밀] 도장. 아래 수치는 화면 구성을 보여주기 위한 **예시값**이며, 현재 인카운터·이벤트·마석 보상 구조에서 재현 가능한 확정 결과가 아니다. 발표 목업에는 사용할 수 있지만 밸런스 근거로 인용하지 않는다.

```text
┌─────────────────────────────────────────────┐
│            괴 이 탐 사 국                     │
│         정기 탐사 결과 보고서                  │
│                                  [ 기 밀 ]   │
│                                             │
│  탐사 번호      제 1차 정기 탐사               │
│  결과          임무 완수                      │
│  최종 도달      제 10구역 (경계 개체 제거 확인)   │
│                                             │
│  회수량        영혼석 87 — 정상                │
│  지급 승인      마석 80                       │
│  제거 개체      11                           │
│  회수 유물      1 (처분: 반출 1)               │
│                                             │
│  인원 변동                                   │
│   투입 4 · 복귀 4 · 소실 1 · 재편성 1          │
│   ~~Soren Blackmoor~~ — 제 7구역, 기록 말소    │
│                                             │
│  특이 접촉      3건                          │
│   * 제 3구역: 방치 야영지 — 물자 회수 승인       │
│                                             │
│  정신 오염 보고  1건 — 교정 불요               │
│                                             │
│  본 보고서는 열람 후 자동 폐기됩니다.            │
│  다음 탐사 브리핑이 발송되었습니다.              │
│  출발 기한: 즉시                              │
└─────────────────────────────────────────────┘
                              [확인]
```

**양식 규칙**
- 소실 동료는 **이름에 취소선** — 지워지는 개인(07 §3-1 사망 문구와 동일 문법). 클릭/호버 시 사인 한 줄 표시(선택).
- "복귀 4"에 부활·재모집 인원이 그대로 섞여 표기 — **탐사국은 구별하지 않는다**(구현체 설정의 조용한 노출).
- 마지막 3줄은 엔딩 초안(00 §6-5)과 접속 — 보고서가 곧 다음 명령서다.
- 전멸 시: 결과란 "탐사대 소실", 인원 변동 "복귀 0", 말미가 "대체 인력 편성이 완료되었습니다."로 교체(07 §6-3과 연결).

## 4. 수치 → 서사 번역 규칙

시스템 용어를 보고서에 그대로 쓰지 않는다. 번역표:

| 시스템 | 보고서 용어 |
|---|---|
| 층 | 구역 ("제 N구역") |
| 보스 | 경계 개체 |
| 적 처치 | 제거 개체 |
| 동료 사망 | 소실 / 기록 말소 |
| 교회 부활 | 재편성 |
| `?` 선택지 이벤트 | 특이 접촉 |
| 패닉 | 정신 오염 보고 (+ "교정 불요/요망") |
| 오브제 마석 교환 | 환수 |
| 오브제 계승 | 반출 (⚠️ 반출은 규정 위반 뉘앙스 — 후반 회차 떡밥, §5) |

## 5. 회차 연동 변화 (다회차 서사 장치)

> 3순위 "서사 비트 시트"와 연결되는 훅. 보고서는 매 런 반복 노출되므로 **회차에 따른 미세 변화**가 위화감 축적에 최적.

| 회차 | 변화 |
|---|---|
| 1~2회차 | 표준 양식 (위 샘플) |
| 3회차~ | 하단에 흐린 누적 행 노출: "누적 탐사: N회 / 누적 소실: N명" — **N이 플레이어의 실제 횟수보다 크다** (이전 조사관들의 몫이 합산되어 있다는 암시) |
| 5회차~ | "본 보고서는 열람 후 자동 폐기됩니다." 문장에 ⬜ 글리치 — 한 글자가 다른 글자로 잠깐 바뀜 |
| 오브제 계승 선택 시 | "반출 N" 옆에 붉은 스탬프 ⬜ "규정 확인 요망" — 응답 없는 경고 |

> ✅ 누적 수치 방침 확정(2026-07-27): 주인공이 몇 번째인지는 **확정하지 않는다** — 정확한 초기값을 정하지 말고, "플레이어가 실제 플레이한 횟수보다 눈에 띄게 큰 숫자"라는 모호성만 유지 (예: 실제 3회차에 누적 표기 수십 단위). 구체 배율은 구현 시 튜닝.

## 6. 데이터 / 구현 훅

```
RunRecord (런 시작 시 생성, PlayerPrefs/JSON 영속)
├── int runNumber              // 회차 (영구 누적)
├── bool cleared
├── int reachedFloor
├── int killCount / soulStoneEarned / manaStoneEarned
├── LostAlly[] losses          // { displayName, floor, cause }
├── EventLog[] events          // { eventId, choiceIndex }
├── int panicCount / reviveCount
├── ObjetLog[] objets          // { objetId, disposition: Exchanged/Carried }
└── (누적) int totalRuns / totalLosses   // 회차 연동(§5)용
```

| 훅 | 위치(추정) |
|---|---|
| 수집 | 각 이벤트 지점 — 적 사망(EnemyData.Hp), 동료 사망(FellowData.Hp), 이벤트 확정(EventPanel), 패닉(BattleManager 스트레스부), 보상 지급부 |
| 표시 | `BattleManager.Phases.cs` 보스 승리/전멸 분기 → 리포트 패널 → 런 리셋 → 마석 영구 스탯 강화 선택 → 새 런 |
| UI | 오프닝 S01 타자기 컴포넌트 재사용 (04 §3 디자인 가이드 동일) |

## 7. 미결 관리

클리어·전멸 직후 리포트 표시는 확정이다. 소실 동료 사인 표기 수위, 대표 특이 접촉 선정, 글리치·누적 수치, 리포트 스킵 규칙은 [15 D](15_미결_안건표.md)에서 관리한다.
