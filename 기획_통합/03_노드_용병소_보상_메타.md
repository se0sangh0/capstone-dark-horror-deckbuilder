## 1. 맵 노드 설계

### 1-1. 정식 버전 기준 (10층 분기) 진행

> 확정 구조(2026-04-10 / 2026-04-15 층당 선택 구조 명확화)

| 항목      | 값           | 비고             |
| ------- | ----------- | -------------- |
| 총 층 수   | 10층         | 정식 버전 기본값 |
| 층당 갈래   | 3갈래 중 1개 선택 | 분기 구조          |
| 총 방문 노드 | 10개         | 층당 1개 × 10층    |
| 시작 노드   | 1층 고정       |                |
| 화톳불 노드  | 9층 고정       |                |
| 보스 노드   | 10층 고정      |                |

**노드 타입 비율(초안)**: 전투 70% / 이벤트 30% / 보스 10층 고정. (밸런스 테스트 후 조정)
**이벤트 노드 내부 가중치(초안)**: 용병소 40 / 교회 20 / 엘리트 10 / `?` 선택지 이벤트 30. 정확한 생성 비율과 런당 상한은 미결이다.

**자동 생성 알고리즘 방침**
- 각 층은 3개 분기 중 1개 선택, 층별 배열은 사전 정의 가중치 기반 랜덤.
- 연속 같은 타입 3회 이상 방지(재시도 로직). 1·9·10층은 노드 고정.
- 세이브 포인트: 5층 / 10층 진입 시 자동 저장.

### 1-1A. 초기 농경 신앙 테마 배경 진행

최초 구현 테마는 토착신의 지정 좌표를 향해 `야생림 → 협곡 → 경작지 → 성소`로 접근한다. 노드 종류와 3갈래 선택은 기존 알고리즘을 유지하며, 층에 따라 참조하는 환경 배경 풀만 점진적으로 전환한다.

| 층 | 환경 배경 |
|---|---|
| 1~2층 | 야생림 |
| 3층 | 야생림·협곡 혼합 |
| 4~5층 | 협곡 |
| 6층 | 협곡·경작지 혼합 |
| 7~8층 | 경작지 |
| 9층 | 큰 나무 아래 화톳불 쉼터 |
| 10층 | 개방형 목석 성소 |

- 첫 전투 인카운터는 야생림의 채집민이 `FILTERED`로 왜곡된 고블린만 배치한다.
- 경작지의 대표 `?` 이벤트는 `우회한다 / 조사한다 / 제거한다`로 분기하며, 제거를 선택한 경우에만 권속 전투로 전환한다([06 §3-2](06_이벤트_노드.md)).
- 9층 화톳불은 방문 시 기본 회복이 적용되고, 노드를 떠날 때 보호의 불이 꺼진다. 회복량·비용 수치는 [15 H2](15_미결_안건표.md)에서 결정한다.
- 공간의 실제 원형과 `FILTERED` 왜곡은 [13 §3B-5 A-1](13_서사_설정_확정.md)을 따른다.

## 2. 용병소 시스템 명세 (정식 버전)

용병소는 탐색 중 등장하는 **이벤트 노드**로, 파티가 전투를 이어가기 위한 동료를 모집·교체하는 장소다. 핵심 3가지는 ① 사망으로 생긴 빈 슬롯 복구 ② 파티 조합 조정 ③ 새 동료 영입이다. 정식 버전에서는 성급·성향·후속 성장 요소와 연결될 수 있도록 후보와 비용을 데이터로 관리한다.

### 2-1. 범위

**포함**: 진입 / 후보 동료 목록 / 고용 / 후보 리롤 / 파티 편집 / 동료 성장(합성) / 빈 슬롯 보충 / 영혼석 차감 / 성급별 비용 표시
**후속 확장**: 스킬 재롤 / 전직 / NPC 대화 분기 / 복합 성향 시너지 / 상위 성장 트리

### 2-2. 기본 규칙

**진입**: 이벤트 노드 클릭 시 `currentView = 'mercenary'` 전환 → 전용 UI.

**후보 표시**: 후보 저장 공간은 최대 **9칸**이며, 화면에는 그중 **3인**을 동시에 표시한다. 각 후보는 이름·직업·역할·모집 비용·성향을 보여 한 화면에서 비교한다.

**고용**:
- 대기석 동료 선택 → 고용, 영혼석이 모집 비용만큼 차감.
- 모집 비용은 [02_동료_적_데이터 §2](02_동료_적_데이터.md)의 `starGrade`와 성급별 기본 비용을 사용한다: 1성 30 / 2성 75 / 3성 180. 샤먼의 최종 비용은 상세 밸런스와 함께 미결이다.
- 후보의 성급과 비용은 함께 표시하며, 성급에 따른 스탯·스킬 메리트는 [02 §2](02_동료_적_데이터.md)의 성급별 성장 배율과 동기화한다.
- 파티 4명 미만이면 빈 슬롯 우선 채움. 4명이면 예비대 보관 후 파티 편집/성장 단계에서 재배치한다.
- 후보 저장 공간은 **9칸**, 동시 표시 수는 **3인**이다.

**리롤**:
- 비용 지불해 후보 목록 재생성, 기존 후보는 폐기되고 새 3인으로 교체.
- 리롤 비용은 해당 노드 내에서만 누적. 최초 **영혼석 2**, 두 번째부터 직전 비용 +1씩 (2→3→4…).
- 노드를 벗어나면 누적 초기화. 무한 반복 가능(밸런스 시 상한 가능).

**파티 편집**:
- 전투 중이 아닐 때만 가능. 현재 파티 4칸 + 대기열 동료 목록 함께 표시.
- 위치 순서 변경 / 대기열 동료로 교체 / 빈 슬롯 즉시 배치 가능.
- 만석이면 기존 1명 ↔ 대기열 1명 교체. 편집 즉시 반영.
- 현재 덱의 성향·역할 구성 표시. (추후 직업/성향 시너지 대시보드 확장)

**동료 성장(합성)**:
- 용병소의 **성장 탭**에서 동일 성급 동료 3명을 소모해 상위 성급 동료 1명을 만든다.
- 결과 동료는 즉시 전투 투입하지 않고 예비대에 저장한 뒤, 파티 편집에서 재배치한다.
- 기본 규칙은 4가지 케이스로 통일한다.
  - 같은 역할 + 같은 성향 → 상위 성급 **동일 역할·동일 성향**
  - 같은 역할 + 다른 성향 → 상위 성급 **동일 역할·랜덤 성향**
  - 다른 역할 + 같은 성향 → 상위 성급 **랜덤 역할·동일 성향**
  - 다른 역할 + 다른 성향 → 상위 성급 **랜덤 역할·랜덤 성향**

### 2-3. 흐름

```text
진입:  event 노드 클릭 → onNavigate('mercenary') → currentView='mercenary' → MercenaryOfficePanel
고용:  후보 선택 → 모집 → 비용 확인 → (부족=실패 / 충분=차감) → 획득 → (빈슬롯=즉시 합류 / 만석=예비대 보관)
리롤:  리롤 → 비용 확인 → (부족=실패 / 충분=차감) → 후보 3인 재생성
편집:  파티 편집 진입 → 배치 순서 변경 / 예비대↔파티 교체 / 빈 슬롯 보충
성장:  재료 3명 선택 → 합성 규칙 판정 → 상위 성급 결과 생성 → 예비대 저장
```

### 2-4. 예외 처리
- **영혼석 부족**: 고용/리롤 미실행, 명확한 실패 메시지.
- **파티 만석**: 자동 합류 X, 예비대 보관 또는 편집 단계에서 교체.
- **빈 슬롯**: 용병소에서는 신규 모집으로 채우고, 교회에서는 사망 동료 부활로 복구한다. 동료 획득 이벤트가 편입되면 해당 결과로도 채울 수 있다.
- **중복 직업**: 허용.
- **후보 수 부족**: 기본 후보군 사용, 정식 버전은 항상 3명 보이도록 보정.
- **구매 가능 후보 보장**: 현재 보유 영혼석 이하의 모집 비용을 가진 후보를 최소 1명 포함한다. 3인 모두 구매 불가 상태로 생성되면 후보 1인을 교체해 선택 가능한 후보를 보정한다.

### 2-5. UI 구성
- 상단: 현재 영혼석 / 파티 상태
- 탭: 파티 모집 / 파티 구성 / 동료 성장
- 중앙: 선택 메뉴 내용 / 우·하단: 고용·리롤·닫기 / 부가: 선택 후보 상세
- 피드백: 비용 부족=빨강 경고 / 고용 성공=알림 / 리롤=목록 즉시 갱신 / 교체=파티 즉시 반영

### 2-6. 데이터 테이블 (예시)

**리롤 비용 상태**: `rerollBaseCost(2)`, `rerollIncrement(+1)`, `rerollCount`, `effectiveRerollCost`
**후보 데이터**: `allyId`, `displayName`, `jobClass`, `role`, `starGrade`, `maxHp`, `stressResist`, `recruitCost`, `skill1`, `skill2`
**성장 데이터**: `sourceFellowIds[3]`, `sameRole`, `sameAffinity`, `resultStarGrade`, `resultRole`, `resultAffinity`
**UI 상태**: `isOpen`, `selectedCandidateIndex`, `rerollCount`, `canRecruit`, `canReroll`, `selectedGrowthSources`

### 2-7. 밸런스 기준
- 용병소는 보상 노드가 아니라 **"복구 노드"** — 손해 일부 회복 가능하나 무조건 이득은 아님.
- 고용은 일정 비용 요구, 리롤은 선택적 소비(노드 내 반복 억제 수준으로 증가).
- 후보 3인 중 최소 1명은 현재 파티에 의미 있는 선택지가 되도록 구성. 너무 강한 후보 연속 방지.
- 성장 탭은 장기 덱 운영의 축이지만, 초반 런을 합성 강제 게임으로 만들지 않도록 1성 모집과 성급 상승의 기대값을 따로 밸런싱한다.

## 3. 보상 시스템 명세 (런 내부 재화)

> 확정 구조 (2026-05-26). ⚠️ 영혼석 드롭 수치는 임시값 — 적 수 확정·밸런스 후 조정.

| 항목 | 내용 |
|---|---|
| 즉시 보상 종류 | 영혼석만 (카드 추가 없음) |
| 지급 방식 | 적 처치 시 바닥에 오브젝트 드롭 → 자동 수거(연출용) |
| 지급 시점 | 처치 즉시 |

> 이 절은 **런 내부에서 바로 쓰는 재화(영혼석)** 만 다룬다. 마석은 아래 §4의 별도 메타 성장 구조로 관리한다.

### 3-1. 시작 영혼석 / 드롭량

- **런 시작 시 보유 영혼석: 20개.**

| 적 | 드롭량 | 비고 |
|---|---|---|
| 고블린 | 8개 | 일반(약) |
| 약탈자 | 12개 | 일반(강) |
| 거두는 자 | 20개 | 보스 고정 |

**일반 전투 조합 참고(3마리 기준)**: 고블린 3 = 24 / 고블린 2+약탈자 1 = 28 / 약탈자 3 = 36

### 3-2. 정식 런 수지 기준

정식 버전은 층별 인카운터와 이벤트 선택에 따라 수입·지출이 달라지므로 고정 시퀀스 대신 아래 산식으로 관리한다.

```text
런 종료 영혼석 = 시작 영혼석 20
              + 처치한 적의 soulStoneReward 합계
              - 모집·리롤 지출
              + 이벤트 선택 결과
```

| 항목 | 정식 기준 |
|---|---|
| 시작 영혼석 | 20 |
| 일반 적 보상 | 고블린 8 / 약탈자 12 등 적 데이터별 합산 |
| 엘리트 보상 | 개체별 20~22 등 적 데이터별 합산 |
| 보스 보상 | 거두는 자 20 / 기록관 30 |
| 모집 비용 | 1성 30 / 2성 75 / 3성 180 |
| 리롤 비용 | 2부터 시작, 노드 내에서 1씩 증가 |

> 정식 10층에서는 전투·엘리트·이벤트 방문 수가 런마다 달라진다. 특정 층에서 모집이 반드시 가능하다고 가정하지 않고, 후보 구매 가능 보정과 이벤트의 코스트 없는 선택지로 자원 고갈을 방지한다.

### 3-3. 연출 (영혼석 드롭 오브젝트)
- 적 처치 위치에 영혼석 스폰 → 약 0.5초 후 자동 수거 애니(UI 방향으로 빨려듦). 플레이어 인터랙션 없음. Unity **Object Pooling** 권장.

### 3-4. 조정 대상
- 정식 인카운터별 영혼석 기대값과 엘리트 드롭량은 [08_밸런스_난이도_아키타입](08_밸런스_난이도_아키타입.md)의 조합표와 함께 플레이테스트한다.
- 오브제(유물)는 엘리트 처치 10% 드롭, 보스 클리어 시 마석 교환·계승 흐름으로 관리하며 상세 규칙은 [09_오브제_유물_시스템](09_오브제_유물_시스템.md)을 따른다.

## 4. 마석 메타 성장 (영구 스탯 강화 방향 확정 · 상세 수치 미정)

### 4-1. 확정 원칙

- **마석(Magic Stone)**은 반복 런에서 획득하고 런 사이에 소비하는 영구 메타 재화다.
- 마석은 **계정 공용 영구 스탯 강화**에 소비한다. 특정 동료·스킬·세계관을 해금하는 재화로 사용하지 않는다.
- 성장 감각의 레퍼런스는 **《Vampire Survivors》의 재화 소비형 PowerUp 구조**다. 레퍼런스의 수치를 복제하지 않고, 반복 플레이로 재화를 모아 기본 능력치를 단계적으로 올리는 흐름만 따른다.
- 클리어와 전멸 모두 런 종료 리포트를 먼저 표시한 뒤 다음 런 준비 단계로 이동한다.
- 런 종료 시 파티·예비대·영혼석은 런 초기값으로 리셋하지만, 마석 잔액과 확정된 메타 진행은 유지한다.
- 강화 효과는 차원 테마와 무관하게 적용하며, 특정 세계관의 동료 구성이나 테마 진입을 요구하지 않는다.

```text
[클리어 또는 전멸]
        ↓
[런 종료 리포트]
        ↓
[런 상태 리셋 / 마석 유지]
        ↓
[영구 스탯 강화 선택]
        ↓
[새 런 시작]
```

### 4-2. 재설계가 필요한 이유

세계관마다 등장하는 동료는 같은 역할군이라도 **외형과 스킬 구성이 달라질 수 있다**. 따라서 마석 성장을 동료 이름·패시브·시그니처 스킬에 귀속하지 않고, 모든 테마에 공통 적용되는 **별도 스탯 강화 축**으로 분리한다.

종전 문서의 `5동료 × 패시브 3종`, `시그니처 스킬 5종`, `총 730 마석`, `카드 10종`, `전체 해금 7~10런` 계산은 **현행 기획에서 폐기**한다. 기존 패시브·스킬 아이디어는 재설계 시 후보 효과로만 참고하며, 해금 단위나 비용의 근거로 사용하지 않는다.

### 4-3. 확정 구조와 남은 상세

| 항목 | 확정 방향 | 결정 필요 |
|---|---|---|
| 성장 단위 | 계정 공용 스탯을 단계별 강화 | 강화 스탯 목록, 항목별 최대 레벨 |
| 영속 범위 | 런과 차원 테마를 넘어 유지 | 세이브 슬롯 간 공유 여부 |
| 보상 구조 | 반복 런에서 마석 획득 | 전투·엘리트·보스 지급량, 클리어·전멸 차등 여부 |
| 소비 구조 | 마석을 소비해 영구 스탯 레벨 상승 | 단계별 비용 곡선, 선행 조건, 환불·초기화 여부 |
| 효과 구조 | 구매 즉시 이후 모든 런에 적용 | 레벨당 증가량, 합연산·곱연산 방식, 적용 시점 |
| UI | 보유 마석·현재 레벨·다음 효과·비용 표시 | 목록형 PowerUp 패널의 배치와 연출 |

### 4-4. 구조 확정 전 안전 규칙

차원 테마의 공통 콘텐츠 계약은 [13 §3B-1~4](13_서사_설정_확정.md)를 따른다. H1의 상세 수치가 결정되기 전에도 아래 규칙은 유지한다.

- 각 강화 항목은 표시 이름과 분리된 안정 식별자 `statUpgradeId`로 저장한다.
- 영구 스탯 강화는 모든 차원 테마에 동일하게 적용하고 동료 표시 이름·외형·스킬 ID를 참조하지 않는다.
- 신규 테마는 마석 강화가 0인 상태에서도 기본 파티·기본 덱으로 진입할 수 있어야 한다.
- 마석 강화는 특정 테마의 입장권이나 특정 동료의 사용 조건이 될 수 없다.
- H1 확정 전에는 임시 데이터에 비용·필요 런 수를 하드코딩하지 않는다.

> 상세 안건은 [15 H1](15_미결_안건표.md)에서 관리한다. 수치가 확정되기 전에는 강화 항목 수·총비용·완주 런 수를 고정값으로 인용하지 않는다.
